STEP 4 - apply the saved Gen2X config with the start flag
RESULT: HTTP 200 - feature ACTIVATES, confirmed in status

    PUT /cloud/start   {"applyImpinjGen2X": true}

GET /cloud/status DURING the inventory:

    "impinjGen2X": {"feature": "tagProtect", "isActive": true}     <-- ACTIVE
    "radioActivity": "active"

Compare before the start call: {"feature":"none","isActive":false}. So this flag
is what moves the saved configuration into effect.

*** THE FEATURE IS PER-SESSION, NOT PERSISTENT ***

After PUT /cloud/stop:

    "impinjGen2X": {"feature":"none","isActive":false}

It reverts. And a subsequent plain start (no flag) does NOT re-apply it - a
second inventory started with {} showed feature:none while the tagProtect config
was still saved and returned by GET /cloud/impinjGen2X.

So applyImpinjGen2X:true must be sent on EVERY start where the feature is wanted.
The reader confirms this in its own response text:

    "Note: Gen2X will not auto-start on reboot (normal mode will resume)."

...though the reality is stronger than that note suggests: it does not carry over
between inventory sessions either, not just across reboots.
