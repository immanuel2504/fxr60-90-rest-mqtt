STEP 5 - disableTagVisibility (reader should stop reading protected tags)
RESULT: HTTP 200, stored - target tag STILL VISIBLE

    {"tagProtect": {"action": "disableTagVisibility", "password": "A1B2C3D4"}}

NOTE THE SHAPE: no tagID. This is the schema's second oneOf branch, which is
reader-scoped rather than tag-scoped - it controls whether THIS READER can see
protected tags, not which tags are protected. The schema requires tagID to be
OMITTED here, and requires it for enableTagProtection/disableTagProtection.
That distinction is easy to miss and is worth calling out in the documentation.

The target was still read. Since the tag was never actually protected (see the
report), this is consistent - there was no protected tag to hide. It does not
independently prove disableTagVisibility is broken.
