STEP 2 - verify the access password by reading RESERVED back
RESULT: HTTP 200 - password CONFIRMED on the tag

Read words 0-3 (both passwords) with a READ access operation, same filter.

BEFORE the write (step 01):
    x95  ["0000000000000000"]
         kill password   = 00000000
         ACCESS password = 00000000     <-- unset, the factory default

AFTER the write:
    x122 ["a1b2c3d4a1b2c3d4"]
         kill password   = a1b2c3d4
         ACCESS password = a1b2c3d4     <-- CONFIRMED, matches what was written

*** ALWAYS DO THIS STEP ***

The WRITE returns "SUCCESS" per tag, but reading the value back is the only way
to confirm the password is actually on the tag. That matters because every
tagProtect call later returns HTTP 200 whether or not the password is valid (see
step 03), so a bad password produces no error anywhere - this read is the only
checkpoint.

NOTE wordCount, not wordCounter. The spec's own with_accesses example uses
"wordCounter", which the firmware rejects:
    "Failure: wordCount must be included in access-config object for read"
