unique == total reads, i.e. each tag reported once in this window - the same
single-report behaviour as INVENTORY at a long interval, even though CONVEYOR
takes no modeSpecificSettings. The example does set

    antennaStopCondition = {"type":"DURATION","value":100}
    query.session = "S1", target = "A", tagPopulation = 200

S1/target A is the session combination that gives each tag a persistence window
before it can be re-inventoried, which is consistent with the one-report-per-tag
result.

CONVEYOR accepted the same shape as CONVEYOR/INVENTORY without complaint. No
CONVEYOR-specific modeSpecificSettings object is documented (the schema's oneOf
offers only inventorySettings and portalSettings), so there is nothing
conveyor-specific to configure through this field - worth confirming with Zebra
whether that is intended.
