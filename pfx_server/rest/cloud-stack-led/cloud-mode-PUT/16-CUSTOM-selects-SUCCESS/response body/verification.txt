This is a Gen2 select with a TID mask (800600 at pointer 6, length 24) and
sel: NOT_SL, so the reader inventories only tags whose selected flag is NOT set
after the select is applied. Tags whose TID matches the mask are asserted and
therefore excluded.

So a split result is the expected shape of a working select - it is
discriminating between tags on their TID contents. From test 09 the reference
tags' TIDs are:

    ...e471  TID e2806894200040017790e471
    ...ac71  (TID captured in test 09's raw data)

Both are Impinj (E280...) but the mask targets bits that differ between them.

NOT FULLY VERIFIED: which specific tags the mask should match was not computed
bit-by-bit, so "the select works" is inferred from the discrimination rather than
predicted in advance. Recording it as observed. A rigorous test would compute the
expected matching set from each tag's TID and compare - worth doing if selects
are important to an integration.

What IS solid: the payload is accepted, and the tag population returned differs
from the unfiltered runs in a way consistent with a select being applied.
