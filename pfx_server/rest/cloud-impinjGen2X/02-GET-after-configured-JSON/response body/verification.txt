WHY THE EARLIER CAPTURE WAS EMPTY
---------------------------------
The endpoint reflects stored Gen2X configuration. On 2026-09-05 no Gen2X
feature had ever been set on the reader, so it returned a bare newline. After
any successful PUT /cloud/impinjGen2X it returns the stored object.

The config is STICKY -- there is no way to return to the empty state:

  PUT /cloud/impinjGen2X {}
  -> 422 {"code":1,"message":"Invalid payload for set_impinjGen2X api"}

So the 1-byte response can only be observed on a reader that has never had
Gen2X configured. Confirmed by attempting the clear above.

The GET always echoes the LAST feature configured, not a merge of all features.
PUT is wholesale: setting tagFocus replaces a stored fastID object entirely.
This follows from the reader's own rule that exactly one feature may be
configured per request:

  PUT {"fastID":{"enabled":true},"tagFocus":{"enabled":true}}
  -> 422 "Only one Impinj Gen2X feature can be configured at a time
          (fastID, tagProtect, tagFocus, or tagQuieting)"
