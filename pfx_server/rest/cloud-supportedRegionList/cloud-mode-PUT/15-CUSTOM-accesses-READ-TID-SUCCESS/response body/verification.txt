The Gen2 READ operation executes per tag and its result is returned in an
"accessResults" ARRAY - one entry per configured access. 6 words = 12 bytes =
24 hex characters, which matches the value returned.

NOTE THE READ VOLUME: 173 total reads from 22
unique tags - the reference tags read 11 and 9 times. This is by far the highest
read count of any test here, because this payload sets no reportFilter and no
interval, so every inventory round re-reports every tag. Combined with an access
operation per tag, that is a lot of RF work and a lot of events.

Practical implication: accesses without a reportFilter produces a very high event
rate. But the two cannot be combined - the schema forbids reportFilter together
with accesses, and the reader enforces it (test 16). So high event volume is
unavoidable when using access operations, unless the mode's own interval is used
instead.

That is worth raising with Zebra: the natural way to throttle an access-heavy
configuration is exactly the combination the API prohibits.
